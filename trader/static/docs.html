Overview

This is an event-driven intraday paper-trading bot for Alpaca. It combines three information sources to make trading decisions:

  1. Market scanner — polls Alpaca's screener for top movers and most active stocks, dynamically building a watchlist instead of relying on hardcoded tickers.
  2. News stream — real-time WebSocket feed of Benzinga headlines. Symbols mentioned in news are added to the watchlist; news on held positions triggers immediate re-evaluation.
  3. Technical signals — SMA crossover and RSI on 5-minute bars, same as before but now applied to the dynamic watchlist.

When a signal fires, an enrichment step assembles a case file (bars + news + scanner context + portfolio state) and sends it to an LLM judge that approves or vetoes with a confidence score. Risk limits cap everything regardless.

Paper trading only. The broker client is constructed with paper=True; never point this at a live account.

Market Scanner

trader/scanner.py polls two Alpaca screener endpoints every SCANNER_INTERVAL_SECONDS (default 2 minutes) while the stock market is open:

  • Most actives — top 20 stocks by volume
  • Market movers — top 10 gainers and top 10 losers by % change

Discovered symbols are added to a dynamic watchlist with a TTL of 30 minutes. Each re-mention (from scanner or news) refreshes the TTL and boosts the symbol's score. Stale entries are pruned automatically. The watchlist is capped at 25 symbols.

The dynamic watchlist is merged with the seed WATCHLIST from config before each stock tick, so the hardcoded tickers are always evaluated as a baseline.

News Stream

trader/news_stream.py runs an Alpaca NewsDataStream WebSocket in a daemon thread, subscribed to "*" (all symbols). Each headline pushes an event onto the shared queue with:

  • headline, summary, source, URL, timestamp
  • all symbols mentioned in the article

The main loop handles news events by:

  1. Adding the symbol to the dynamic watchlist (via scanner.add_from_news)
  2. Recording the news event to trades.jsonl
  3. If the symbol is currently held, immediately enriching and re-evaluating it (news can trigger exits)

Free tier: news is delayed ~15 minutes. The $99/mo Algo Trader Plus plan provides real-time news.

The Tick Cycle

trader/main.py runs an event-driven loop with three timer-based triggers:

  1. Scanner poll (every 2 min) — calls scanner.poll_screener(), pushes new discoveries as SCANNER_HIT events.
  2. Crypto tick (every 5 min, always) — evaluates CRYPTO_WATCHLIST through signals + judge.
  3. Stock tick (every 5 min, market hours only) — evaluates the merged dynamic + seed watchlist through signals + enrichment + judge.

Between timers, the loop drains the event queue (news and scanner hits) with a 1-second timeout. Hard exits (stop-loss/take-profit) are checked at the start of each crypto and stock tick, before signal evaluation.

Signal Engine

trader/signals.py is intentionally simple and fully deterministic — the same bars always produce the same signal, which makes the judge's contribution measurable.

Indicators

IndicatorDefinitionParameters
SMA fastmean of last N closesN = 9 bars (45 min)
SMA slowmean of last N closesN = 21 bars (105 min)
RSI100 − 100/(1+RS), RS = avg gain / avg loss over N bars N = 14, oversold < 30, overbought > 70

Rules

ConditionHolding?Signal
SMA fast crosses above slow (and RSI not overbought)No buy — momentum entry
RSI drops below 30No buy — mean-reversion entry
SMA fast crosses below slowYes sell — momentum faded
RSI rises above 70Yes sell — take the froth

A "cross" requires the relationship to have flipped between the previous bar and the current bar — a fast SMA merely being above the slow one is not a signal, which prevents re-firing every tick during a trend.

Enrichment

trader/enrichment.py builds a case file for each candidate symbol before it goes to the judge. A case file contains:

  • Recent 5-minute bars (from data.py)
  • Last 5 news headlines and summaries for the symbol (REST call to Alpaca news API)
  • Scanner context: how the symbol was discovered, its score, volume/move data
  • The technical signal (if any)
  • Current portfolio state (account + positions)

This is the key difference from the old architecture: the judge now sees why a stock is moving, not just that it moved.

The LLM Judge

trader/judge.py plays devil's advocate. It receives every candidate signal with its full case file and is prompted to be skeptical.

Enhanced prompt

The prompt now includes:

  • Proposed trade (side, symbol, rule, indicators)
  • Last 40 five-minute bars
  • Recent news headlines for the symbol
  • Discovery context (scanner source, score, % move, volume)
  • Portfolio state (account + positions)

The contract

{ "decision": "approve" | "veto", "confidence": 0.0–1.0, "reason": "one sentence" }

Fail-safe

Timeout, non-zero exit code, malformed JSON, or an illegal decision value all resolve to veto with confidence 0. A broken judge can never cause a trade.

Event Log Schema

logs/trades.jsonl is append-only, one JSON object per line, each with a ts (UTC ISO 8601) and an event discriminator:

signal — a rule fired and the judge ruled on it

{"event": "signal", "symbol": "NVDA", "side": "buy",
 "rule": "SMA fast crossed above slow",
 "indicators": {"price": 512.3, "sma_fast": 511.8, "sma_slow": 511.2, "rsi": 58.1},
 "verdict": {"decision": "approve", "confidence": 0.78, "reason": "..."},
 "ts": "2026-08-14T15:05:12+00:00"}

entry — an approved buy was submitted

{"event": "entry", "symbol": "NVDA", "qty": 19, "price": 512.3,
 "rule": "SMA fast crossed above slow", "ts": "..."}

exit — a position was closed

{"event": "exit", "symbol": "NVDA", "reason": "take-profit (3.12%)",
 "position": {"qty": 19, "avg_entry_price": 512.3, "current_price": 528.3,
              "unrealized_plpc": 0.0312, "market_value": 10037.7}, "ts": "..."}

news — a headline was received from the news stream

{"event": "news", "symbol": "NVDA", "headline": "NVIDIA Q3 earnings beat estimates",
 "summary": "...", "source": "Benzinga", "url": "...",
 "created_at": "2026-08-14T14:30:00+00:00", "ts": "..."}

scanner — a new symbol was discovered by the screener

{"event": "scanner", "symbol": "PLTR", "source": "scanner", "score": 1.0,
 "scanner_meta": {"pct_change": 4.2, "volume": 85000000}, "ts": "..."}

Runbook

# one-time setup
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # paste Alpaca PAPER keys

# run both bot + dashboard (Ctrl-C stops both)
make run

# or separately:
python -m trader.main        # terminal 1: the bot
python -m trader.dashboard   # terminal 2: dashboard at http://localhost:8600

Troubleshooting

SymptomLikely cause
Dashboard shows "Alpaca unavailable"missing/invalid keys in .env; the event feed still works from local logs
Every verdict is judge error (codex failed) codex CLI logged out or model config issue — run codex exec --ignore-user-config "say OK" manually to check
No signals for hoursnormal in flat markets; crossovers are rare by design. Check the scanner panel — if it's discovering symbols, the pipeline is working.
Scanner panel is emptyscanner only runs while the stock market is open. Crypto ticks still run 24/7.
News feed is emptycheck NEWS_STREAM_ENABLED in config; free tier news is 15-min delayed but should still appear. Check logs for WebSocket errors.
Bars look different from your charting app free IEX feed has thinner volume than the paid SIP feed
