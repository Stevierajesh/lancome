Overview

This is a hybrid intraday paper-trading bot for Alpaca. "Hybrid" means the decision to trade passes through two independent layers plus a hard safety net:

  1. Rules propose — deterministic technical indicators (SMA crossover, RSI) scan a watchlist every 5 minutes and emit candidate signals. Crypto pairs are scanned 24/7; stocks only while the market is open. Crypto entries are notional (dollar-amount, GTC) orders; stock entries are whole-share DAY orders. Note: position symbols drop the slash (BTC/USD → BTCUSD).
  2. The LLM judges — each candidate is sent to an LLM (via the codex CLI, running on a ChatGPT subscription — zero per-token cost) which approves or vetoes it with a confidence score.
  3. Risk caps everything — position sizing, position count, daily loss halt, and per-position stop-loss/take-profit run regardless of what the first two layers say.
⚠ Paper trading only. The broker client is constructed with paper=True; never point this at a live account.

The Tick Cycle

trader/main.py runs an infinite loop. Every POLL_INTERVAL_SECONDS (300s) during market hours it executes one tick:

  1. Snapshot — fetch account equity/cash and open positions from Alpaca.
  2. Hard exits first — every open position is checked against stop-loss (−2%) and take-profit (+3%). These exits bypass the judge entirely: safety rules are not up for debate.
  3. Fetch bars — last ~100 five-minute bars per watchlist symbol from the free IEX feed.
  4. Evaluate signals — each symbol runs through the signal engine. Symbols already held can only produce sell signals; unheld symbols only buy.
  5. Daily-loss gate — if equity is down ≥2% vs yesterday's close, all new buys are skipped for the rest of the day.
  6. Judge — surviving signals go to the LLM with full context (bars, indicators, portfolio). Only approve with confidence ≥ 0.6 proceeds.
  7. Size & execute — buys are sized to ≤10% of equity (whole shares, capped by cash); sells close the whole position. Market orders, day time-in-force.
  8. Record — every signal, verdict, entry, and exit is appended to logs/trades.jsonl.

Any exception inside a tick is caught and logged; the loop never dies mid-session. If the market is closed, the tick is skipped.

Signal Engine

trader/signals.py is intentionally simple and fully deterministic — the same bars always produce the same signal, which makes the judge's contribution measurable.

Indicators

IndicatorDefinitionParameters
SMA fastmean of last N closesN = 9 bars (45 min)
SMA slowmean of last N closesN = 21 bars (105 min)
RSI100 − 100/(1+RS), RS = avg gain / avg loss over N bars N = 14, oversold < 30, overbought > 70

Rules

ConditionHolding?Signal
SMA fast crosses above slow (and RSI not overbought)No buy — momentum entry
RSI drops below 30No buy — mean-reversion entry
SMA fast crosses below slowYes sell — momentum faded
RSI rises above 70Yes sell — take the froth

A "cross" requires the relationship to have flipped between the previous bar and the current bar — a fast SMA merely being above the slow one is not a signal, which prevents re-firing every tick during a trend.

The LLM Judge

trader/judge.py plays devil's advocate. It receives every candidate signal and is prompted to be skeptical — veto anything that looks weak, choppy, or contradicted by recent price action.

How it's invoked

codex exec \
  --sandbox read-only \          # judge cannot run commands or write files
  --skip-git-repo-check \
  --ephemeral \                  # no session state saved
  --ignore-user-config \         # avoids a retired model pinned in ~/.codex/config.toml
  --output-schema judge_schema.json \
  --output-last-message /tmp/<file> \
  "<prompt>"

Because this goes through the codex CLI's ChatGPT-subscription auth, judge calls cost no API credits. A call takes ~15–60s, which is fine at a 5-minute cadence, and the judge only runs when a rule actually fires — most ticks make zero LLM calls.

The contract

--output-schema forces the reply to match trader/judge_schema.json:

{ "decision": "approve" | "veto", "confidence": 0.0–1.0, "reason": "one sentence" }

The prompt includes the proposed trade, the rule that fired, current indicator values, the last 40 bars, and the account/positions snapshot.

Fail-safe

Timeout (120s), non-zero exit code, malformed JSON, or an illegal decision value all resolve to veto with confidence 0. A broken judge can never cause a trade — it can only prevent them. Set JUDGE_ENABLED = False in config to run a rules-only baseline for comparison.

Event Log Schema

logs/trades.jsonl is append-only, one JSON object per line, each with a ts (UTC ISO 8601) and an event discriminator:

signal — a rule fired and the judge ruled on it

{"event": "signal", "symbol": "NVDA", "side": "buy",
 "rule": "SMA fast crossed above slow",
 "indicators": {"price": 512.3, "sma_fast": 511.8, "sma_slow": 511.2, "rsi": 58.1},
 "verdict": {"decision": "approve", "confidence": 0.78, "reason": "…"},
 "ts": "2026-08-14T15:05:12+00:00"}

entry — an approved buy was submitted

{"event": "entry", "symbol": "NVDA", "qty": 19, "price": 512.3,
 "rule": "SMA fast crossed above slow", "ts": "…"}

exit — a position was closed

{"event": "exit", "symbol": "NVDA", "reason": "take-profit (3.12%)",
 "position": {"qty": 19, "avg_entry_price": 512.3, "current_price": 528.3,
              "unrealized_plpc": 0.0312, "market_value": 10037.7}, "ts": "…"}

Every judged signal is logged whether approved or vetoed — vetoes are the interesting data for evaluating whether the judge adds value over raw rules.

Filtering and pagination happen server-side, so the browser only ever holds one page of events regardless of log size.

Runbook

# one-time setup
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # paste Alpaca PAPER keys

# terminal 1 — the bot
python -m trader.main

# terminal 2 — this dashboard
python -m trader.dashboard   # → http://localhost:8600
